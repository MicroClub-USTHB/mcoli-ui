# mcoli-ui

mcoli-ui ships themes and `mc-*` components through a shadcn registry. Components are copied into the project as source (`components/ui/mc-<name>.tsx`), so edit them freely after install.

## Before writing UI

1. Read `DESIGN.md` at the project root if it exists. Its YAML tokens are the source of truth for colors, type, radii and spacing; its prose says when to use each one.
2. Check which components are installed: `ls components/ui/mc-*.tsx`.
3. If `components.json` is missing, stop and ask the user to run `npx shadcn@latest init`; mcoli-ui needs it.

## Setting up a project

Run without prompts so the command never blocks:

```bash
npx mcoli-ui init --theme <primary|secondary|game-dev|robotics|it> --yes
```

This installs the theme CSS variables, writes `DESIGN.md`, and registers the `@mcoli` namespace in `components.json`. An existing `DESIGN.md` is kept unless `--overwrite` is passed. Do not change the theme unless the user asks.

## Adding components

1. Find the component in [references/components.md](references/components.md), or run `npx mcoli-ui list --json` for the live list.
2. Preview, then install all needed components in one call:

```bash
npx mcoli-ui add mc-dialog --dry-run
npx mcoli-ui add mc-button mc-input mc-dialog
```

3. Import from the alias in `components.json`, for example `import { McButton } from '@/components/ui/mc-button'`.

Use an `mc-*` component when one exists. Fall back to plain shadcn/ui components only for what mcoli-ui does not ship, and style them with the same semantic tokens.

## Styling rules

- Use semantic Tailwind tokens: `bg-primary`, `text-primary-foreground`, `bg-surface`, `text-muted-foreground`, `border-border`. Never hardcode hex values or arbitrary values such as `bg-[#0006b1]`.
- Pair each surface token with its `-foreground` token.
- Headings use `header-xl` to `header-xs`; body text uses `paragraph-xl` to `paragraph-xs`.
- Radii come from the theme (`rounded-lg` for buttons, inputs and cards). The Robotics theme is intentionally sharp; do not round it further.
- Dark mode works through the `.dark` class. Do not add `dark:` color overrides for theme tokens.

## Checking your work

After changing UI, run the project's type check and lint (for example `pnpm typecheck && pnpm lint`), then compare the result against the Do's and Don'ts in `DESIGN.md`. Fix any hardcoded colors or radii before finishing.
